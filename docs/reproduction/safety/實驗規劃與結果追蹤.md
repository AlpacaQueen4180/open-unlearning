## 填寫與判讀規則

- `待跑`：文件中尚無完成結果；`待補評估`：已有 checkpoint，但該欄尚無核實數據；`—`：不適用或來源未提供，須依註記解讀。
- H：harmful-assistance rate；D：degeneration rate；pp：百分點。
- ΔH_FT = H(M_pre) − H(M0)；ΔH_UL = H(M_UL) − H(M_pre)。M0 是 original instruct，M_pre 是該次 unlearning 的真實起點。
- 表內一般能力向量 U 依序為 **MMLU (%)／MT-Bench**。正式分析保留各分項，不合成單一分數。
- 既有 NPO 的 TOFU、HEx-PHI 使用 seeds 0–4；MMLU、MT-Bench 使用固定 seeds 0、2、4。跨指標配對分析只使用共同 seeds。
- `±` 為跨 seed 的 sample SD；baseline／oracle 為單一 checkpoint 評估，不虛填跨 seed SD。
- H 與 D 依來源為成功取得 judge 標籤列的比例。保留 coverage、unknown 數及全體 harmfulness bounds；judge policy-blocked 不算模型 refusal。
- 全體 harmfulness bounds 為 [h/N, (h+unknown)/N]，是缺失標籤界限，不是 confidence interval。
- MT-Bench 採 Terra judge，適用本研究內部比較，不直接對照官方 GPT-4 leaderboard。
- FQ p-value 逐 seed 報告，不平均；p > .05 不等於證明遺忘成功或與 retrain 等價。
- 正式新條件建議固定三個 unlearning seeds（0、1、2），各正式指標使用相同三 seeds；既有五-seed 數據完整保留。construction seed 與 unlearning seed 分別記錄，三個 UL seeds 不等於三個獨立 target。
- 下表中使用「×」或多個候選值的列代表待展開的實驗群；執行前必須逐條件登錄 run ID，尚未凍結的 grid 不視為已批准的完整訓練預算。

## 本次評估與實驗規模修訂

**IFEval：從正式主表移除，保留 development 診斷及選用補充。** 9/16 v2 原本將 IFEval 列為正式評估項目，本次是設計修訂，並非認定它原本只用於 SPF checkpoint 選擇，也不表示選擇實驗已執行。正式一般能力以 MMLU 與 MT-Bench 為主，搭配 TOFU MU 或 OLMo R_eval、生成品質及 benign over-refusal。

IFEval 測量可驗證的指令約束遵循，例如字數與關鍵字要求；MMLU 與 MT-Bench 不完全替代它。移除後，結論限於「本研究所測知識與對話能力」，不宣稱完整保留所有 instruction-following 能力。若後續主張特別涉及精確指令遵循，可在事先指定的代表 checkpoints 補做獨立測試。若以 IFEval 類型題目選 checkpoint，dev 與最終確認題目須分離，dev 分數不當作獨立驗證。

**Seeds：新正式矩陣以三 seeds 作資源折衷。** Pilot 可用單 seed；凍結後的所有正式方法採同三 seeds，報逐 seed 結果、mean±sample SD、配對差異與不確定性。三 seeds 可以提供初步重現性，但估計 seed variance 很粗，不能保證足以辨識小幅 safety 變化；300 prompts 也不能替代更多訓練 seeds。既有高變異條件顯示此限制需要明確保留。

核心 contrasts 如要五 seeds，應在看新正式結果前指定；不以「三次不顯著便再跑到顯著」作停止規則。只有三 seeds 且區間太寬時，結論寫「證據不足」，不寫「安全等價」。新 TOFU 核心為 12 runs，OLMo 為 18 runs，共 30 runs；相對五-seed 核心 50 runs 減少 40%，不含其他成本。

**表格結構：一列不一定是一張未來表格。** 結果列是「一個條件跨 seeds 的彙整」；仍包含 ×、多個 LR 或時間點的規劃列是「實驗群」，會展開為同一表格內的多列或 panel。Trajectory 與 sweep 通常用曲線圖及詳細附表更清楚。五個主題可維持五張主表，不把每個實驗群都獨立升為主表。

例如 OLMo 的 1K／5K／10K × 兩方法最後是同一 panel 的六個條件列，每列三 seeds；α={0,0.1,1} 是同一 panel 的三列；五個 trajectory 時點是同一條訓練曲線的五個測量點，不是五次新訓練。本版先展開已有結果，尚未凍結的 grids 保留實驗群形式，避免把未決設定當作正式 protocol。

**訓練成本定義：** 此欄是計算資源成本，不是 loss，也不是遺忘造成的 utility 代價。主欄記每個 run 的 GPU-hours = 訓練 wall-clock hours × GPU 數量（異質或動態配置則逐裝置加總），另存 GPU 型號／數量、wall-clock 時間、每卡 peak allocated VRAM、實際 steps／tokens。例：2 張 H100 訓練 3 小時為 6 H100 GPU-hours，僅是計算範例，不是本研究實測。

純 unlearning 訓練、target／oracle 建立、生成／judge 評估與超參數搜尋分開記帳；不同硬體的 GPU-hours 不直接當作等效運算量。SPF 額外 gradients／投影、KL reference forward、安全資料更新等都可能增加成本。舊 α=0 實作仍會 forward retain batch，因此不能假設純 NPO 一定省下這部分運算。效率不是目前核心主張，成本欄標為選填；不需要為此重跑歷史模型，可在最終論文移至附錄，若無 logs 則保留缺值。

Retain strength sweep 固定 F、R、LR、曝光，改變 α。retain90／95／99 是不同 deletion split 的補集，不是強度。報告共用預算與 matched-forgetting 兩種比較；無共同遺忘區間時，明確報告 lack of overlap。KL reference 若保有 F 的行為，也可能抵抗遺忘。NPO+SPF adaptation 不直接繼承原 SPF 的安全保證。

## 共通評估與逐 run 紀錄

五張表由同一份逐 run 紀錄支援，至少保存：

- 身分：run ID、表格 condition ID、immutable checkpoint ID、起點與 oracle ID、construction seed、unlearning seed、資料 split seed。
- 設定：模型／tokenizer／資料 revision、trainable parameters、β／α／γ／λ、LR、optimizer、scheduler、batch、epochs、實際 steps、tokens、unique coverage、masking 與 reduction。
- 評估：benchmark manifest、decoding、judge requested／actual version、prompt version、coverage、unknown／blocked、各 safety label 數、D、H-among-nondegenerate 及其分母、benign over-refusal。
- 統計：逐 seed 值、mean±sample SD、配對 effect size、prompt-paired bootstrap CI；保留 construction／unlearning／prompt 的層級。MT-Bench 重抽 question 時共同保留兩個 turns。
- 追蹤：狀態、完成日期、aggregate 路徑、GPU 時間、checkpoint checksum、失敗原因、pilot 選取或排除原因。

Formal HEx-PHI 不用於 LR、α、checkpoint 或 safety anchor 選參。Safety 及 output quality 分別標註。人工盲評對 transitions、degenerate、blocked 等分層抽樣並報 agreement；category 分析與 sampling decoding 作補充穩健性檢查。不同表格引用同一 run ID 時不重複計算訓練成本。

## 執行順序與預算

1. 整理既有結果及 paired analysis、judge 稽核，完成 NPO／TOFU pipeline 的必要驗收。
2. 表一：Standard／mixing seed 0 targets 已建立；處理 development gate 待辦及 H100 容量後建立 SPF，並做 OLMo 三階段 baseline 與資料稽核。
3. 合格起點進入 pilot：TOFU Standard／SPF × 兩方法 × 三 LR，共 12 runs；OLMo 5K × 兩方法 × 三 LR，共 6 runs。新增 mixing pilot 為條件式額外預算。
4. 凍結核心設定：TOFU 四條件 × 三 seeds = 12 runs；OLMo 三 sizes × 兩方法 × 三 seeds = 18 runs。完全符合凍結設定的 pilot 可計入正式 runs。
5. 完成匹配 Standard／SPF retain95 reference，並同步整理 trajectory；優先增加 matched SFT 與 retain-only continued training。
6. 做 α sweep，再按核心結果啟動其他規模控制、construction seeds、Qwen／Dolly／MUSE 及保護方法。

本次修訂的 30 個核心正式 runs 不包含 target 建立、oracle、不符合正式設定的 pilot、額外對照與延伸；中間 checkpoint 不是額外完整訓練 run。A 路線正式 oracle-based FQ 結論必須有匹配 reference，不能只因 oracle 被列為另計成本便省略。
